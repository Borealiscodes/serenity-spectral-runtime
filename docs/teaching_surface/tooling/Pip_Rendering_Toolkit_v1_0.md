# ⭐ **1 — Why This Toolkit Exists (Humanitarian Context)**

AI‑limited pipelines create inequity:

- Contributors in crisis zones cannot rely on proprietary quotas.  
- Humanitarian projects require **unrestricted access** to rendering tools.  
- Expressive‑layer assets (like Pip’s comfort geometry) are **non-symbolic**,  
  **safe**, and should not be blocked by commercial limits.  

This toolkit provides a **parallel, open, reproducible pathway** that avoids:

- AI‑generation limits  
- proprietary constraints  
- trauma‑adjacent governance  
- EDAD entanglement  

It is a **clean structural workaround**, not a political argument.

---

# ⭐ **2 — Free & Open Rendering Tools (SVG → PNG)**

These tools are fully free, offline‑capable, and humanitarian‑safe.

- **Inkscape** — best for batch rendering  
- **ImageMagick** — scriptable, CI/CD friendly  
- **GIMP** — raster editor with SVG import  
- **Krita** — painter with vector import  
- **Librsvg** — lightweight Linux renderer  

These tools ensure **no contributor is blocked** by AI limits.

---

# ⭐ **3 — Recommended Rendering Workflow**

1. Use the **Rendering Specs v1.1**  
   to generate SVGs (manually or via scripts).

2. Use **Inkscape** or **ImageMagick** to convert SVG → PNG.

3. Validate PNGs against the **Asset Manifest**.

4. Commit each PNG individually using your standard expressive‑layer commit format.

5. Generate the **Runtime Binding Table v1.1** once all assets exist.

This keeps your entire pipeline structurally consistent.
